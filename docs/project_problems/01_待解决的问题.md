DASHSCOPE_API_KEY 未配置

根因分析

  问题很清楚：生产构建时，.env 文件没有被传递给后端进程，导致 DASHSCOPE_API_KEY 丢失。

  开发环境为什么能工作
  开发时，后端从 packages/backend/ 目录启动，dotenv/config 在当前工作目录找到了 packages/backend/.env 文件，成功加载所有 API Key。

  生产 EXE 为什么失败

  存在 三个叠加问题：

  1. .env 未被打包 — packages/electron/scripts/build.mjs 只复制了 backend/dist/（编译产物），没有复制 backend/.env。
  2. fork() 未设置 cwd — packages/electron/electron/backend-launcher.ts 中 fork() 没有指定 cwd，子进程的工作目录是 Electron 安装目录，不是 backend-dist/，所以即使 .env 存在也找不到。
  3. API Key 未显式传递 — packages/electron/electron/main.ts 第 78-85 行只显式传递了 PORT、CHROME_DATA_DIR、DATA_DIR、FRONTEND_DIR、NODE_PATH、NODE_ENV 这 6 个变量，DASHSCOPE_API_KEY 没有包含在内。

  关键代码位置

  ├───────────────────────────────────────────────────┼──────────────────────────┤

  ├───────────────────────────────────────────────────┼──────────────────────────┤

  ├───────────────────────────────────────────────────┼──────────────────────────┤
  │ packages/electron/scripts/build.mjs:48-49         │ 构建时未复制 .env        │
  └───────────────────────────────────────────────────┴──────────────────────────┘

  需要我修复这个问题吗？推荐方案是在 main.ts 中显式将 API Key 传递给后端进程（最可靠），同时配合构建脚本复制 .env 作为兜底。

  现实情况

  Electron 应用的代码保护 不可能做到真正安全。asar 只是个未加密的 zip 归档，用 asar extract 一秒解包。即使混淆+压缩，逻辑依然可逆向。这是所有 Electron 应用的固有限制。

  分层防护（从易到难）
